## 2. 已确认的构建入口、CP 模板来源与产物路径

- **构建产物路径规则（源自 `bk_avdk_smp/tools/build_main.mk:123-127`）**：

    `<SDK_DIR>/build/bk7259/<project_name>/package/all-app.bin`

## 3. 已核实的 SDK 内部源码事实 vs 待验证的外设/平台行为

### 3.1 内存、Cache 与帧缓冲（严格区分“SDK API 存在”与“外设 DMA 行为待实测”）
- **已核实的 SDK 静态源码事实（`bk_avdk_smp` `release/v4.0.1.11`）**：
  - **L2 Cache 与 Cache Line**：`ap/middleware/arch/cortex-m/l2_cache.c` 定义 PL310 控制器基址 `L2C_PL310_BASE = 0xA0000000U`，宏 `L2C_CACHE_LINE_SIZE = 32U`（32 字节）。
  - **D-Cache 一致性 API**：`ap/middleware/arch/cortex-m/cache.c` 提供 `bk_dcache_addr_is_cacheable(addr, len)`、`bk_dcache_clean_for_producer(addr, len)` 与 `bk_dcache_invalidate_for_consumer(addr, len)`。
  - **帧队列对齐宏**：`ap/components/bk_frame_buffer/include/bk_frame_queue.h` 定义 `BK_FRAME_QUEUE_ALIGN_SIZE = 64U`；`bk_mem_slab.h` 定义 `ALIGN_BYTES = 64`。
  - **PSRAM 堆 API**：`ap/include/os/mem.h` 提供 `os_sram_malloc()`、`psram_malloc()`（目标构建实测确认无公开 `psram_cache_malloc()` 符号，`bk_port_bk7259.c` 将 `BK_MEM_CAP_PSRAM` 与 `BK_MEM_CAP_PSRAM_CACHEABLE` 统一映射至 `psram_malloc()`）；`projects/beken_robot/partitions/bk7259/ram_regions.csv` 划分了 `PSRAM_MEM_SLAB_UNCODED` (`0x60000000`) 与 `PSRAM_MEM_SLAB_CODED` (`0x64000000`)。
- **待 Tier 2 / Tier 4 实测验证的硬件与外设 DMA 行为（禁止在实测前直接外推）**：
  - 具体外设 DMA（MIPI CSI / DVP 摄像头、JPEG/H.264 硬件编解码器、LCD 显示控制器）在 `bk7259_robot` 上究竟要求绑定 `PSRAM_MEM_SLAB_UNCODED`、`PSRAM_MEM_SLAB_CODED` 还是 `AP_PSRAM_CACHE_HEAP`，以及驱动内部是否已自行执行 Cache Clean/Invalidate，**尚未经过实机验证**。

### 3.2 分区表与 OTA / SecureBoot 现状（已核实阻塞点，OTA 暂缓进入默认交付）
- **SDK 静态代码支持的两种互斥安全 OTA 模式**（`ap/components/ota/Kconfig`）：
  1. `CONFIG_SECURE_OTA_OVERWRITE`（`ap/components/ota/ota_secure_overwrite/ota_secure_overwrite.c`）：将压缩且带 BL2 EC-P256 签名的镜像写入 `ota` 分区，并在 `ota_control` 分区写入 `struct ota_confirm_rec`（`OTA_CONFIRM_REC_MAGIC = 0x4F544143`）。重启后 BL2 解压覆盖 `primary_all` 并执行 **EC-P256 (`ec256`)** 签名校验与 `app_security_counter` 检查。**Overwrite 模式覆盖主分区后不支持启动后回滚旧版本。**
  2. `CONFIG_SECURE_OTA_XIP`（`ap/components/ota/ota_secure_xip/ota_secure_xip.c` & `ota_boot_param.c`）：A/B 双槽位模式（`primary_all` / `secondary_all`），通过 `boot_param` 分区写入 `TRIAL` 记录，由 BL2 执行 EC-P256 校验与未确认回滚。
- **`bk7259_robot` 现有 8MB 分区表的硬限制（已核实）**：
  - `bk_solution_ai/projects/beken_robot/partitions/bk7259/auto_partitions.csv` 定义 `FLASH_CAPACITY=8M`，其中 `primary_cp_app = 1440K`，`primary_ap_app = 6248K`（注释注明实测约 `3700K`），**`ota` 分区仅有 `264K`**，且无 `ota_control` 或 `boot_param` 分区，亦无 robot 16MB 分区表。
  - **结论与门禁约束**：在提交以下 5 项前置证据之前，`bk_ota` 仅作为**暂缓目标能力（Deferred Target Capability）**，不进入默认组件交付：
    1. 针对 `bk7259_robot` 实测重算的具体分区表 CSV；
    2. 实测编译出的 AP 与 CP 镜像准确字节数；
    3. 实测打包出的 OTA 压缩包大小；
    4. 对应的 BL2 安全配置；
    5. 明确选择 `OVERWRITE` 还是 `XIP` 的单一策略决策。
