## 3. 已核实的 SDK 内部机制证据（静态源码核查，待实机验证）

### 3.1 内存、Cache 与帧缓冲（来自 `bk_avdk_smp` `release/v4.0.1.11`）
- **L2 Cache 与 Cache Line**：`ap/middleware/arch/cortex-m/l2_cache.c` 定义 PL310 控制器基址 `L2C_PL310_BASE = 0xA0000000U`，宏 `L2C_CACHE_LINE_SIZE = 32U`（32 字节）。
- **D-Cache 一致性 API**：`ap/middleware/arch/cortex-m/cache.c` 提供：
  - `bk_dcache_addr_is_cacheable(const void *addr, size_t len)`（基于 `CONFIG_PSRAM_MPU_REGION_0..3` 判断）
  - `bk_dcache_clean_for_producer(void *addr, size_t len)`（内部调用 `arch_dcache_flush_range` + `__DSB()`）
  - `bk_dcache_invalidate_for_consumer(void *addr, size_t len)`（内部调用 `arch_dcache_invd_range`）
- **帧队列对齐宏**：`ap/components/bk_frame_buffer/include/bk_frame_queue.h` 定义 `BK_FRAME_QUEUE_ALIGN_SIZE = 64U`；`bk_mem_slab.h` 定义 `ALIGN_BYTES = 64`。
- **PSRAM 堆 API**：`ap/include/os/mem.h` 提供 `psram_malloc()`、`psram_cache_malloc()`（需启用 `CONFIG_AP_PSRAM_CACHE_HEAP_ADDR`）及 `bk_psram_heap_get_used_count()`。

### 3.2 分区表与 OTA / SecureBoot 现状（来自 `bk_avdk_smp` 与 `bk_solution_ai`）
- **SDK 支持的两种互斥安全 OTA 模式**（`ap/components/ota/Kconfig`）：
  1. `CONFIG_SECURE_OTA_OVERWRITE`（`ap/components/ota/ota_secure_overwrite/ota_secure_overwrite.c`）：将压缩且经 BL2 签名的镜像（`"BK723658"` 魔数头 + 非取反 CRC32）写入 `ota` 分区，并在 `ota_control` 分区末尾写入 `struct ota_confirm_rec`（`OTA_CONFIRM_REC_MAGIC = 0x4F544143`）。重启后 BL2 解压覆盖 `primary_all` 并执行 **EC-P256 (`ec256`)** 签名校验（见 `projects/secureboot_overwrite/partitions/bk7259/security.csv`）及 `app_security_counter` 检查（见 `ota.csv`）。**注：Overwrite 模式覆盖主分区后不支持新固件启动失败自动回退旧版本。**
  2. `CONFIG_SECURE_OTA_XIP`（`ap/components/ota/ota_secure_xip/ota_secure_xip.c` & `ota_boot_param.c`）：A/B 双槽位模式（`primary_all` / `secondary_all`），通过 `boot_param` 分区写入 Ping-Pong `TRIAL` 记录，由 BL2 执行 EC-P256 校验与未确认回滚。
- **`bk7259_robot` 现有 8MB 分区表的 OTA 限制（重要发现）**：
  - `bk_solution_ai/projects/beken_robot/partitions/bk7259/auto_partitions.csv` 定义 `FLASH_CAPACITY=8M`，其中 `primary_cp_app = 1440K`，`primary_ap_app = 6248K`（注释注明实测约 `3700K`），**`ota` 分区仅有 `264K`**，且无 `ota_control` 或 `boot_param` 分区。
  - 在 `bk_avdk_smp/projects/app/partitions/bk7259/auto_partitions.csv`（8M 默认表）中，`primary_cp_app = 1900K`，`primary_ap_app = 1156K`，`ota = 1900K`。
  - **结论**：`bk7259_robot` 若要启用完整固件 OTA，必须先重新规划分区表（从 `primary_ap_app` 释放空间给 `ota` 并补齐控制分区，或使用 16M 分区表）；在此之前，安全 OTA 与回滚只能作为**待验证目标能力**，不能声明为已具备的板级能力。
